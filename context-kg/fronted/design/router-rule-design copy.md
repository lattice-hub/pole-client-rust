# 路由规则编辑 — 设计交接文档

> 适用范围：Pole.IO 治理工作台 → 规则类型 = **路由（RouteRule）** 编辑抽屉里的 **「规则」Tab**。
> **本次只关注「规则」Tab 的设计**；版本、审计等其它 Tab 暂不在本文档范围内。
> 本文档描述「规则」Tab 的布局结构、字段、交互、校验与生成的规则 Spec，供 Codex 实现参考。
> 视觉体系基于 Ant Design 风格（浅灰底 `#f0f2f5` + 白卡片 + 主色 `#1677ff`），原型见 `index.html`。

---

## 1. 「规则」Tab 整体结构

编辑入口为**右侧抽屉**（宽 `min(1180px, 92vw)`），从右滑入，遮罩可点击关闭，`Esc` 关闭。抽屉内有 Tab 切换，下文仅描述**「规则」Tab**选中时的内容：

```
「规则」Tab（左右两栏）
├── 左：表单区（可滚动）
│   ├── ① 基础信息
│   ├── ② 服务范围（可折叠）
│   └── ③ 路由规则
└── 右：实时规则 Spec 预览（深色，YAML/JSON 可切换，可复制）

抽屉底部栏：校验状态摘要 + 取消 / 保存并下发
```

分段标题统一样式：圆形蓝色序号 + 标题 + 灰色说明文字。

---

## 2. ① 基础信息

仅包含规则的标识与基本属性（**不含命名空间/服务**，作用域已抽到 ② 段）：

| 字段 | 控件 | 说明 | 必填 |
|---|---|---|---|
| 规则名称 | 文本框 | kebab-case（小写字母/数字/连字符） | 是 |
| 优先级 | 步进器（− 值 +） | 整数 0–100，数值越大越优先 | 否（默认 5）|
| 描述 | 多行文本 | 自由文本 | 否 |
| 规则标签 | 标签 chip + "编辑标签" | `key:value` 形式，可增删 | 否 |
| 启用状态 | 开关 | 开=保存后立即下发数据面 | 否（默认开）|

---

## 3. ② 服务范围（调用关系，可折叠）

表达规则作用的**调用关系**：主调方 → 被调方。

### 3.1 展开态
一张三栏布局的「服务调用图」：

```
┌─ 主调（蓝色顶边）──────┐      ┌─ 被调（青色顶边）──────┐
│ [↗icon] 主调          │      │ [▤icon] 被调          │
│         发起调用方     │  ◯→  │         目标服务方     │
│ ─────────────────────│ 圆形 │ ─────────────────────│
│ 命名空间 ▾ | 服务 ▾    │ 箭头 │ 命名空间 ▾ | 服务 ▾    │
└──────────────────────┘      └──────────────────────┘
```

- 左右各一张**白色节点卡**（`border-top` 区分：主调蓝 `#1677ff`、被调青 `#13c2c2`）。
- 卡头：方形图标（主调=外发箭头，被调=服务器堆叠）+ 角色标题 + 小字副标题 + 下分隔线。
- 卡内字段**左右并排**（命名空间 / 服务两个下拉），压缩高度。
- 中间：白底蓝边的**圆形箭头节点**，垂直居中，表达 A→B 方向。
- 字段：`主调命名空间 / 主调服务 / 被调命名空间 / 被调服务`，均为下拉选择。

### 3.2 折叠态
点击 ② 段标题栏即可折叠。折叠后标题栏右侧显示一行 mono 摘要：

```
spec-governance/spec-order  →  spec-governance/spec-payment
```

（右侧箭头 `▸` 旋转表示展开/折叠状态。）

### 3.3 长文本悬浮
服务名过长时：下拉框内用省略号截断，**鼠标悬浮**显示完整 `命名空间/服务`（自定义深色气泡 tooltip，非原生 title；自动避让视口边缘）。折叠摘要的两段同样支持悬浮显示全名。

### 3.4 响应式
窄屏（< 1100px）时，两张节点卡上下堆叠，中间箭头旋转为向下。

## 4. ③ 路由规则

命中匹配条件的请求，按目标分组的权重转发。支持**多条规则块**（自上而下匹配），右上角显示「N 条」，底部「添加规则」。

每条规则块（卡片）含两个子区：

### 4.1 子区① 匹配条件
- **关系切换**：`AND`（需同时满足全部条件）/ `OR`（满足任一即命中），分段按钮。
- **条件表格**，列：

| 列 | 控件 | 取值 |
|---|---|---|
| 参数类型 | 下拉 | `HEADER` / `QUERY` / `PATH` / `COOKIE` / `METHOD` |
| 参数键 | 输入框 + datalist 联想 | 随参数类型联动候选键（如 HEADER→x-tenant/x-user-type/region…）|
| 匹配类型 | 下拉 | `完全匹配` / `前缀匹配` / `正则匹配` / `包含` / `不等于` |
| 匹配值 | 输入框 | 期望值 |
| 操作 | 删除按钮 | 至少保留 1 行 |

- 「添加匹配条件」追加一行。切换参数类型时，参数键自动重置为该类型的首个候选。

### 4.2 子区② 目标分组
- 分组表格，列：

| 列 | 控件 | 说明 |
|---|---|---|
| 分组名称 | 输入框（前缀色块标识分组）| 如 `payment-blue` |
| 是否隔离 | 小开关 | 实例隔离 |
| 权重 | 数字输入（%） | 整数 |
| 实例标签 | 输入框 | 如 `lane=blue version=v2` |
| 操作 | 删除按钮 | 至少保留 1 行 |

- **权重实时校验**：表格下方有权重条（按分组比例着色）+ 合计百分比。
  - 合计 = 100% → 绿色「✓ 已满 100%」。
  - ≠ 100% → 红色「需等于 100% · 差 X%」。
- 「添加实例分组」追加一行。

## 5. 实时 Spec 预览（右栏）

随表单编辑实时生成，可切换 **YAML / JSON**，可一键复制。底部显示校验摘要（通过 / N 项待修复 + 首条提示）。

### 5.1 Schema（YAML 示例）

```yaml
apiVersion: governance.pole.io/v1
kind: RouteRule
metadata:
  name: spec-check-route          # 基础信息.规则名称
  enabled: true                   # 基础信息.启用状态
  priority: 5                     # 基础信息.优先级
  labels:                         # 基础信息.规则标签
    - owner:codex
    - scenario:sample
spec:
  source:                         # ② 服务范围.主调
    namespace: spec-governance
    service: spec-order
  destination:                    # ② 服务范围.被调
    namespace: spec-governance
    service: spec-payment
  description: spec RouteRule + CustomRoute sample
  rules:                          # ③ 路由规则（数组，支持多条）
    - match:
        relation: AND             # AND / OR
        conditions:
          - { param: HEADER, key: x-tenant, op: 完全匹配, value: vip }
          - { param: QUERY,  key: region,   op: 包含,     value: "ap-guangzhou,ap-shanghai" }
      route:                      # 目标分组（权重合计须=100）
        - { group: payment-blue,   isolate: false, weight: 80, labels: "lane=blue version=v2" }
        - { group: payment-stable, isolate: false, weight: 20, labels: "lane=stable version=v1" }
```

> 字段映射：`metadata` ← ①基础信息；`spec.source/destination` ← ②服务范围；`spec.rules[].match/route` ← ③路由规则。
> 落地实现时建议把中文枚举（`完全匹配`/`AND` 等）映射为后端枚举值（如 `EXACT`/`PREFIX` 等），UI 层保留中文展示。

## 6. 校验规则（保存时）

保存前全量校验，任一不通过则拦截保存、Toast 提示首条错误，并高亮对应字段：

1. 规则名称必须符合 kebab-case（`^[a-z][a-z0-9-]*$`）。
2. 每条规则的目标分组**权重合计必须 = 100%**（否则提示「规则[i] 权重合计 X%」）。
3. 不允许存在**未命名分组**。
4. 不允许存在**空匹配值**。

校验通过 → 写入持久化（原型用 localStorage）→ Toast「已保存并下发到数据面」→ 关闭抽屉。

## 7. 视觉令牌（参考 `brand-spec.md`）

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#f0f2f5` | 页面底 |
| `--surface` | `#ffffff` | 卡片 / 抽屉 |
| `--fg` | `rgba(0,0,0,.88)` | 主文字 |
| `--muted` | `rgba(0,0,0,.45)` | 次要文字 |
| `--border` | `#ebedf0` | 发丝分隔线 |
| `--accent` | `#1677ff` | 主色（按钮/开关/编号/链接）|
| 被调色 | `#13c2c2` | 被调节点强调 |
| `--success` | `#52c41a` | 权重达标 / 启用 |
| `--danger` | `#ff4d4f` | 校验错误 / 权重不足 |

- 字体：正文 `-apple-system, PingFang SC, Microsoft YaHei, system-ui`；数值/ID/Spec 用 mono（`SF Mono / JetBrains Mono`），开启 `tabular-nums`。
- 圆角：卡片 8px、输入/按钮 6px、编号徽标圆形。
- 边框：1px 发丝线；仅抽屉/下拉/气泡用浅投影。主色每屏克制使用（主操作 + 编号/开关）。
