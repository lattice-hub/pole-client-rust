# 无损上下线规则编辑 — 设计交接文档

> 适用范围：Pole.IO 治理工作台 → 规则类型 = **无损（LosslessRule）** 编辑抽屉里的 **「规则」Tab**。
> 本文档只描述「规则」Tab 的页面结构、字段交互、Spec 映射、保存校验和实现注意点；版本、审计等其它 Tab 不在范围内。
> 视觉体系沿用现有 Ant Design 控制台风格：浅灰页面底、白色卡片、蓝色主操作、右侧实时 Spec 预览。原型见 `index.html`。

---

## 1. 设计目标

无损上下线规则不是通用流量策略，也不是探测规则的复制。它表达的是服务实例生命周期里的三段治理：

```
一个治理对象
├── 无损上线：延迟注册
│   ├── 时长延迟
│   └── 探测延迟：HTTP / TCP / UDP 健康检查
├── 服务预热：注册后渐进接流
└── 无损下线：等待存量请求完成
```

关键约束：

- 无损上线没有「触发阶段」字段，不要加 `trigger`。
- 延迟注册策略只有「时长延迟」和「探测延迟」。
- 探测延迟必须先选择协议，再根据协议配置探测目标，最后配置检查间隔。
- 探测延迟协议支持 `HTTP / TCP / UDP`。
- `TCP / UDP` 探测延迟必须支持「发送报文 + 响应匹配 + 匹配方式」。
- 服务预热字段保持为：启用、预热时长、终止保护、终止百分比、曲线值。
- 预热曲线值范围为 `1～5`，对应算法里的 `curvature`。
- 无损下线只有一个用户配置项：等待时长。摘流、停止新流量、连接排空是默认执行行为，不作为用户可配置项展示。

## 2. 「规则」Tab 整体结构

右侧抽屉，左表单 / 右实时 Spec 双栏。无损规则的分段顺序：

```
① 基础信息                    —— 名称 / 优先级 / 描述 / 标签 / 启用状态
② 治理对象                    —— 主调命名空间 / 服务名称
③ 无损上线 · 延迟注册          —— 上线保护、延迟策略、健康检查
④ 服务预热 · 渐进放量          —— 预热窗口、终止保护、曲线值
⑤ 无损下线 · 等待时长          —— 下线保护、等待间隔
```

- ① 基础信息：与其它规则一致，只放规则标识和通用属性。
- ② 治理对象：表达规则作用的服务实例集合，不展示调用关系图。
- ③～⑤ 是无损规则的生命周期配置，三块可以分别启停。
- 保存时至少启用一项无损能力，否则提示用户配置无效。

无损上线 / 下线作用的服务实例集合

## 4. ③ 无损上线 · 延迟注册

### 4.1 顶层启停

字段：

| 字段 | 控件 | 说明 |
|---|---|---|
| 上线保护启用 | 开关 | 关闭后，实例启动完成后立即注册到注册中心 |

关闭态文案：

```text
已关闭，实例启动完成后立即注册到注册中心
```

开启后展示「延迟注册策略」。

### 4.2 延迟注册策略

使用两张策略卡：

| 策略 | Spec 值 | 说明 |
|---|---|---|
| 时长延迟 | `TIME_DELAY` | 实例启动后等待固定秒数，再注册到服务发现。适合启动耗时稳定的服务。 |
| 探测延迟 | `PROBE_DELAY` | 持续调用实例健康检查目标，只有探测成功后才暴露实例，避免未就绪接流。 |

不要展示「触发阶段」。不要生成 `delayedRegistration.trigger`。

### 4.3 时长延迟

当策略为「时长延迟」时显示：

| 字段 | 控件 | 说明 | 校验 |
|---|---|---|---|
| 延迟注册时长 | 数字输入 + 秒后缀 | 实例启动后固定等待的秒数 | 不能小于 0 |

摘要文案：

```text
注册条件：实例启动后等待 {N}s，到时直接进入服务发现列表。
```

Spec 映射：

```json
{
  "enabled": true,
  "strategy": "TIME_DELAY",
  "delaySec": 15
}
```

### 4.4 探测延迟

当策略为「探测延迟」时显示三步式健康检查配置。

#### 第 1 步：检查协议

字段：

| 字段 | 控件 | 取值 |
|---|---|---|
| 检查协议 | 分段按钮 | `HTTP` / `TCP` / `UDP` |

交互要求：

- 协议必须先选。
- 后续第 2 步根据协议切换表单。
- 探测延迟默认使用实例对应协议端口，不提供单独端口配置。

#### 第 2 步：按协议配置探测目标

当协议为 `HTTP`：

| 字段 | 控件 | 说明 | 校验 |
|---|---|---|---|
| 请求方法 | 下拉 | `GET` / `POST` / `HEAD` | 必须是允许值 |
| 检查路径 | 文本输入 | 如 `/healthz` | 不能为空 |

当协议为 `TCP` 或 `UDP`：

| 字段 | 控件 | 说明 | 校验 |
|---|---|---|---|
| 匹配方式 | 下拉 | `完全匹配` / `包含匹配` / `正则匹配` | 必须是允许值 |
| 发送报文 | 多行文本 | 请求报文，可为空；例如 `PING\n` | 可为空 |
| 响应匹配 | 多行文本 | 期望响应内容；例如 `PONG` | 不能为空 |

TCP/UDP 说明文案：

```text
默认使用实例 {协议} 协议端口；仅当响应报文匹配成功后注册。
```

#### 第 3 步：检查间隔

字段：

| 字段 | 控件 | 说明 | 校验 |
|---|---|---|---|
| 检查间隔 | 数字输入 + 秒后缀 | 探测失败时多久重试一次 | 必须大于 0 |

注册条件摘要：

- HTTP：

```text
每 {intervalSec}s 调用 {method} {path}，健康检查成功后注册；失败期间实例不进入可发现列表。
```

- TCP/UDP：

```text
每 {intervalSec}s 通过 {protocol} 发送报文，并按 {match} 比对响应，健康检查成功后注册；失败期间实例不进入可发现列表。
```

提示卡片：

| 标题 | 文案 |
|---|---|
| 接口来源 | 由业务实例自身暴露，不复用治理探测规则。 |
| 端口语义 | 默认使用实例协议端口，不要求单独填写。 |
| 失败处理 | 只延迟注册，不摘除已有健康实例。 |

## 5. ④ 服务预热 · 渐进放量

服务预热在实例完成注册后生效，用于让新实例在一段时间内逐步接流。

### 5.1 顶层启停

字段：

| 字段 | 控件 | 说明 |
|---|---|---|
| 预热启用 | 开关 | 关闭后，新实例注册后直接按完整权重接流 |

关闭态文案：

```text
已关闭，新实例注册后直接按完整权重接流
```

开启后展示三步配置：预热窗口、终止保护、预热曲线值。

### 5.2 第 1 步：预热窗口

字段：

| 字段 | 控件 | 说明 | 校验 |
|---|---|---|---|
| 预热时长 | 数字输入 + `Second` 后缀 | 新实例保持预热态的持续时间 | 预热启用时必须大于 0 |

说明文案：

```text
开启预热后，新实例不会立即按完整权重接流；该时间窗内由治理层按预热曲线逐步放量。
```

### 5.3 第 2 步：终止保护

字段：

| 字段 | 控件 | 说明 | 校验 |
|---|---|---|---|
| 预热终止保护 | 开关 | 控制是否允许按终止百分比提前结束预热 | 无 |
| 预热终止百分比 | 数字输入 + `%` 后缀 | 仅在终止保护开启时显示 | 0–100 |

说明文案：

```text
开启后，当实例承接流量达到配置百分比时，治理层可结束预热保护并进入正常接流。
```

默认推荐值：

```text
80%
```

### 5.4 第 3 步：预热曲线值

字段：

| 字段 | 控件 | 说明 | 校验 |
|---|---|---|---|
| 预热曲线值 | 数字输入 | 算法里的 `curvature` | 非空时必须是 `1～5` 的整数 |

文案必须准确表达真实算法：

```text
范围 1～5，值越大末段爬升越陡。
```

算法说明：

```java
double ww = ((double) uptime / warmup.getIntervalSecond());
double result = Math.ceil(Math.abs(Math.pow(ww, warmup.getCurvature()) * baseWeight));
weight.setDynamicWeight(result > baseWeight ? baseWeight : (int) result);
```

可视化要求：

- 用曲线图解释 `curvature` 对权重增长的影响。
- 横轴：预热时间进度，0% → 100%。
- 纵轴：动态权重占比，0% → 100%。
- 曲线按 `ceil((uptime / intervalSecond) ^ curvature * baseWeight)` 归一化生成。
- `curveValue = 5` 时，前段增长较慢，末段陡升。例如 0/25/50/75/100% 时间点大致对应 0/1/4/24/100% 权重。

注意：

- 不要把曲线值解释成“值越大整体增长越快”。在 0～1 区间的幂函数里，曲线值越大，前段越慢、末段越陡。
- 不要新增 `startPercent / targetPercent / curve` 这类字段。
- 留空表示系统默认曲线；如果后端要求必填，再把默认值改为 3 并调整校验。

### 5.5 当前配置摘要

在预热配置末尾展示只读摘要：

```text
当前配置：注册后进入 {seconds} Second 预热窗口；终止保护 {开启，阈值 {percent}% | 关闭}；曲线值 {curveValue | 默认}，对应 {曲线形态}。
```

## 6. ⑤ 无损下线 · 等待时长

无损下线只暴露一个用户配置项：等待时长。

### 6.1 顶层启停

字段：

| 字段 | 控件 | 说明 |
|---|---|---|
| 下线保护启用 | 开关 | 关闭后，实例注销时不等待存量请求完成 |

关闭态文案：

```text
已关闭，实例注销时不等待存量请求完成
```

### 6.2 下线等待

字段：

| 字段 | 控件 | 说明 | 校验 |
|---|---|---|---|
| 无损下线间隔 | 数字输入 + `Second` 后缀 | 实例注销前等待存量请求自然完成的时长 | 启用时必须大于 0 |

只读说明：

```text
默认执行行为：实例进入下线流程后，系统默认先从流量入口摘除并停止接收新请求，然后按上方间隔等待存量连接 / 请求完成。连接排空与摘流不再作为用户配置项展示。
```

说明下方可展示三个只读步骤 chip：

```text
默认摘流 / 停止新流量 / 等待存量请求
```

禁止实现为用户可配置项：

- 下线模式
- 新请求处理
- 强制下线兜底
- 事件通知开关
- 摘流策略
- 连接排空策略

这些都是默认执行机制，不暴露给用户。

## 7. 前端数据模型

当前原型使用的前端状态可按下列结构理解：

```js
{
  name: 'spec-check-lossless',
  enabled: true,
  priority: 5,
  desc: 'spec LosslessRule 无损上下线样例',
  tags: ['owner:codex', 'scenario:sample'],
  scope: {
    ns: 'spec-governance',
    svc: 'spec-order'
  },
  delayReg: {
    on: true,
    strategy: '探测延迟', // '时长延迟' | '探测延迟'
    seconds: 15,
    check: {
      protocol: 'HTTP', // HTTP | TCP | UDP
      method: 'GET',
      path: '/healthz',
      intervalSec: 5,
      payload: {
        request: 'PING\n',
        response: 'PONG',
        match: '包含匹配'
      }
    }
  },
  warmup: {
    on: true,
    seconds: 0,
    curveValue: '',
    protect: true,
    percent: 80
  },
  offline: {
    on: true,
    waitSec: 30
  }
}
```

字段说明：

- `delayReg.check.payload` 只在 `protocol = TCP / UDP` 时进入 Spec；HTTP 下不输出 payload。
- `delayReg.check.method/path` 只在 `protocol = HTTP` 时进入 Spec；TCP/UDP 下不输出 method/path。
- `warmup.seconds = 0` 可作为初始草稿值，但启用预热后保存必须拦截。
- `warmup.curveValue = ''` 表示系统默认曲线。
- `offline.waitSec` 是无损下线唯一用户配置项。

## 9. 保存校验

保存时按规则类型整体校验：

### 9.1 总体校验

- `delayReg.on / warmup.on / offline.on` 至少启用一项。

### 9.2 延迟注册

当 `delayReg.on = true`：

- 时长延迟：
  - `delaySec` 不能小于 0。
- 探测延迟：
  - 协议必须是 `HTTP / TCP / UDP`。
  - `intervalSec` 必须大于 0。
  - HTTP：
    - 方法必须是 `GET / POST / HEAD`。
    - 路径不能为空。
  - TCP/UDP：
    - 匹配方式必须是 `完全匹配 / 包含匹配 / 正则匹配`。
    - 响应匹配内容不能为空。
    - 发送报文可以为空。

### 9.3 服务预热

当 `warmup.on = true`：

- `durationSec` 必须大于 0。
- 若 `terminationProtect = true`，`terminationPercent` 必须在 `0–100`。
- `curveValue` 非空时必须是 `1～5` 的整数。

### 9.4 无损下线

当 `offline.on = true`：

- `waitIntervalSec` 必须大于 0。
- 不校验下线模式、摘流模式、新请求处理、强制下线等字段，因为这些字段不应存在。

## 10. 实现清单

落地到代码时建议按以下顺序处理：

- [ ] 新增或确认 `LosslessRule` 类型入口与规则卡片。
- [ ] 基础信息沿用现有通用组件。
- [ ] ② 治理对象只包含命名空间和服务。
- [ ] ③ 延迟注册：
  - [ ] 顶层开关。
  - [ ] 两张策略卡：时长延迟 / 探测延迟。
  - [ ] 时长延迟字段：延迟注册时长。
  - [ ] 探测延迟三步：协议 → 探测目标 → 检查间隔。
  - [ ] HTTP 子表单：方法 / 路径。
  - [ ] TCP/UDP 子表单：匹配方式 / 发送报文 / 响应匹配。
  - [ ] 不实现触发阶段。
- [ ] ④ 服务预热：
  - [ ] 顶层开关。
  - [ ] 预热时长。
  - [ ] 终止保护 + 终止百分比。
  - [ ] 曲线值 `1～5`。
  - [ ] 按真实算法绘制权重增长曲线图。
  - [ ] 不实现起始流量、目标流量、曲线枚举、阶段数组。
- [ ] ⑤ 无损下线：
  - [ ] 顶层开关。
  - [ ] 无损下线间隔。
  - [ ] 默认执行行为只读说明。
  - [ ] 不实现下线模式、新请求处理、强制下线兜底、事件通知开关。
- [ ] 同步右侧 Spec 预览。

- [ ] 用默认样例跑一次渲染、Spec 和校验检查。

## 11. 反回归清单

实现或后续修改前，逐项检查：

- [ ] 页面没有「触发阶段」。
- [ ] Spec 没有 `delayedRegistration.trigger`。
- [ ] 探测延迟协议不是固定 HTTP，必须支持 `HTTP / TCP / UDP`。
- [ ] TCP/UDP 探测延迟不是空协议选择，必须有报文匹配配置。
- [ ] 探测延迟不要求填写端口，默认使用实例协议端口。
- [ ] 服务预热没有 `startPercent / targetPercent / curve`。
- [ ] 预热曲线值不是任意非负数，范围是 `1～5`。
- [ ] 曲线图解释的是幂函数后段陡升，不写成“值越大整体越快”。
- [ ] 无损下线只剩等待时长。
- [ ] 连接处理、摘流、新请求处理、强制下线兜底没有作为用户配置项出现。
